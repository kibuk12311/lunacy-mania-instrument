# Анализатор данов для osu!mania 4K: описание проекта

Дата: 2026-10-24

## Зачем

Пока я листаю карты в song select osu!stable, рядом лежит небольшое окошко. Оно само показывает, какой дан у выбранной карты и какие в ней паттерны.

Сейчас для этого есть несколько калькуляторов: Daniel, Companella, Mania Tracker, анализатор LeoBlack и Dan-Overlay. Они часто расходятся друг с другом на целый уровень. Мне нужен **один сводный ответ** по дану и паттерну, точнее любого из них по отдельности.

Приложение я буду раздавать друзьям, поэтому оно должно работать «само»: скачал, запустил, работает.

## Цели

1. Отдельное окно Windows. Когда в osu!stable выбирают карту в song select, окно само показывает:
   - **дан** словом и числом, например «Gamma low/mid · 12.8» (Gamma = 13, 12.8 = 13 − 0.2 → low/mid);
   - **уверенность** и примерный разброс, например «уверенность высокая · ±0.3»;
   - **главный паттерн** и доли трёх главных паттернов полосками;
   - **метки**: Tech (если есть), BPM, длительность карты.
2. Моды и рейт (DT, HT, нестандартный рейт) учитываются: при смене модов дан пересчитывается.
3. Сводный дан по точности **превосходит Mixed** (LeoBlack, его использует Mania Tracker): средняя абсолютная ошибка на отложенных картах бенчмарка меньше 0.31 уровня, среднее смещение близко к нулю. Если не выйдет, сказать об этом честно и показать цифры.
4. Приложение работает «само»:
   - одна программа, никаких настроек при первом запуске;
   - tosu спрятан внутри, без окна, без консоли, браузер не открывает;
   - вместе с приложением закрывается и tosu.

## Не цели

- LN-карты, Mix-карты, 7K и другие раскладки. Для них в окне просто пишется «не 4K рис» (или «LN-карта»), без дана.
- Личный дан игрока по скорам, загрузка реплеев, рейтинги, сайт.
- Оверлей поверх игры или внутриигровой оверлей. Нужно именно отдельное окно.
- Публикация в интернете. Приложение раздаётся только друзьям лично.
- Экран или файл с лицензиями и благодарностями. Пока не нужен: оригинальные файлы `LICENSE` внутри папок со взятым чужим кодом остаются как есть, новые не добавляются.

## Анти-цели (что считать провалом, даже если всё технически работает)

- Окно показывает уверенный дан на карте, где калькуляторы сильно расходятся. При разногласии уверенность должна честно падать.
- Метка «Tech» загорается на каждом обычном стриме с плавающим BPM.
- Друзьям приходится что-то настраивать, ставить tosu или Node, или искать папку osu!.
- Появляется консольное окно или сам открывается сайт tosu.
- Точность «лучше всех» получена на тех же картах, на которых модель обучалась.

## Как выглядит окно (выбрано: вариант B, «карточка»)

```
Gamma low/mid   12.8
уверенность высокая · разброс ±0.3

Jumpstream
Jumpstream  ████████░░  46%
Handstream  ████░░░░░░  22%
Chordjack   ███░░░░░░░  15%
[Tech] [200 BPM] [2:41]
```

- Интерфейс **только на русском**.
- **Подписи данов** (решено пользователем), ступени внутри уровня по порядку: `low`, `low/mid`, `mid`, `mid/high`, `high`.
  - Уровни 1–10: «7 low/mid», «10 high».
  - Дальше греческие буквы: Alpha, Beta, Gamma, Delta, Epsilon, Zeta, Eta, Theta, Iota, Kappa. Например, «Gamma mid/high».
  - Короткие имена, без «Reform» и без префиксов вроде «Emik Zeta». Ниже 1-го дана пишется «ниже 1 дана», выше Kappa — «выше Kappa».
  - **Числовая шкала** как в бенчмарке LeoBlack: 1–10 — даны, Alpha = 11 … Kappa = 20. Ступень определяется дробной частью: смещение от целого −0.5…−0.3 → low, −0.3…−0.1 → low/mid, −0.1…+0.1 → mid, +0.1…+0.3 → mid/high, +0.3…+0.5 → high. Это решение строителя, подписи — решение пользователя.
- Окно сделано для разных раскладок, потому что у друзей экраны разные:
  - запоминает своё место и размер;
  - переключатель «поверх всех окон»;
  - компактный режим.
- Состояния окна:
  - ожидание osu! — «Ждём osu!…»;
  - карта считается — короткий индикатор;
  - не 4K или LN — «не 4K рис» / «LN-карта»;
  - ошибка разбора — короткое сообщение.
- Во время игры окно может оставаться как есть, потому что это отдельное окно. Прятать его не обязательно.

## Как это работает

### Получение текущей карты: tosu спрятан внутри (решено пользователем)

- Внутри приложения лежит **tosu** (https://github.com/tosuapp/tosu). Приложение запускает его скрытым фоновым процессом, без окна и без значка, и останавливает при выходе.
- Перед запуском приложение записывает конфиг tosu:
  - `OPEN_DASHBOARD_ON_STARTUP=false` — не открывать сайт (просьба пользователя);
  - `ENABLE_AUTOUPDATE=false` — tosu обновляется только вместе с приложением;
  - `CALCULATE_PP=false` — экономия процессора;
  - `SERVER_IP=127.0.0.1` — доступ только с этого компьютера;
  - `SERVER_PORT` — свой порт, не стандартный 24050, чтобы не конфликтовать с чужим tosu;
  - `ENABLE_INGAME_OVERLAY=false`.
- Приложение подключается к WebSocket tosu и берёт оттуда:
  - путь к `.osu` выбранной карты;
  - моды и рейт;
  - состояние игры (song select, игра, результаты).
- Клиент только **osu!stable**. lazer не поддерживается.
- Свой поиск данных в памяти osu! (без tosu) отклонён: он ломается при обновлениях osu!, и его пришлось бы поддерживать самим. Позже его можно поставить на место tosu, не трогая анализатор.

### Расчёт: сводная модель поверх существующих калькуляторов

Для каждой карты с учётом рейта считается следующее.

**Готовые калькуляторы**, по возможности взятые как есть из анализатора LeoBlack https://github.com/LeoBlackMT/osumania_map_analyser (папка `ManiaMapAnalyser by Leo_Black/js/`, JS, работает и в браузере, и в Node):

| Калькулятор | Где лежит | Что даёт |
|---|---|---|
| Sunny | `rework/sunnyAlgorithm.js` | звёзды, доля LN, раскладка |
| Daniel | `rework/danielAlgorithm.js`, `estimator/danielEstimator.js` | дан Alpha–Theta |
| Azusa | `estimator/azusaEstimator.js` | дан по всей шкале |
| Roxy | `estimator/roxyEstimator.js` | дан, только для уровней 11–17 |
| Companella | `estimator/companellaEstimator.js` + `dan_model.onnx` (onnxruntime) | дан по всей шкале |
| Mixed | `estimator/mixedEstimator.js` | для сравнения и как отдельный признак |

**MinaCalc MSD**: Overall и 7 скиллсетов, через WASM-сборки в `js/ett/versions/`.

**Признаки паттернов**: поиск паттернов в стиле Interlude из `js/patterns/` (кластеры, их важность, флаг «Mixed», то есть неровный ритм).

**Собственные признаки карты** (на усмотрение строителя): число нот, длительность, плотность, доли аккордов, баланс рук и т.п.

Поверх всего этого работает **сводная модель**: регрессия, которая из ответов калькуляторов и признаков делает один непрерывный дан.

- Тип модели (ridge, градиентный бустинг, стекинг и т.п.) выбирает строитель. Условие одно: модель маленькая и быстро считается в приложении. Веса экспортируются в JSON или ONNX.
- **Уверенность** строится из разброса ответов калькуляторов и из того, насколько модель ошибается на похожих картах при проверке. Разброс «±» показывается в уровнях дана.

**Паттерн:**
- Главный паттерн и доли трёх главных паттернов берутся из поиска паттернов LeoBlack: доля паттерна = его длительность от суммы длительностей.
- **Метка Tech** ставится, только если выполнены оба условия:
  1. главный кластер паттернов «Mixed», то есть ритм в нём гуляет на 5 мс и больше;
  2. MSD Technical близок к главному скиллсету (например, не ниже ~93% от него; точный порог подбирает строитель по бенчмарку).
- Цель метки: не загораться на каждом стриме с плавающим BPM.

**Кеш:** результаты сохраняются по хешу `.osu` + рейт, поэтому повторно выбранная карта показывается мгновенно.

**Целевое время** от выбора карты до показа результата: меньше 1–2 секунд на обычной карте.

### Данные для обучения и проверки

- Бенчмарк LeoBlack: https://github.com/LeoBlackMT/VSRG-DanEstimation-Benchmark
  - `samples/data.csv` — ~1350 карт 4K с ручной разметкой дана (`expected`) и типа паттерна (course / jack / speed / stamina / tech / ln);
  - сами `.osu` лежат в `samples/samples.7z`;
  - имена файлов карт содержат рейт (например «x1.35»), а сами `.osu` уже ускорены.
- Нам нужны только RC-карты, без категории `ln`.
- Карты бенчмарка **не попадают в приложение** (авторские права, `samples/Disclaimer.md`). Они используются только локально для обучения и проверки. В приложение идут только веса модели.
- **Честная проверка:** перекрёстная проверка, где разбиение делается **по песням/наборам карт**, а не по отдельным файлам. Иначе одна и та же карта на разных рейтах окажется и в обучении, и в проверке.
- Важно: Azusa и Roxy сами подгонялись под этот бенчмарк, поэтому их ответы как признаки «знают» ответы. Строитель должен это учитывать:
  - сравнивать с Mixed на тех же отложенных картах;
  - отдельно смотреть, что даёт модель без Azusa и Roxy.
- В `data.csv` поле `expected` — число на этой же шкале (например 11.5, 13.2, 17.8): целое значит mid, ±0.2 значит low/mid или mid/high. Это и есть цель обучения. Чаще всего встречаются дробные части .0, .2 и .8.
- **Что значит «лучше Mixed»** (решение строителя). Mixed прогоняется на **тех же отложенных картах** при **том же разбиении по песням**, только на RC-картах (без `ln`), со всеми копиями на разных рейтах. Наша средняя ошибка должна быть ниже, чем у Mixed в этом же прогоне. Число 0.31 — просто ориентир из опубликованных результатов. Смещение по модулю ≤ 0.1.
- **Azusa и Roxy как входы** (решено пользователем: «как предложил»). Считаются и показываются обе версии модели, с ними и без них. В приложение идёт та, что лучше на картах, которых нет ни в нашем обучении, ни, насколько это можно установить, в калибровочных данных Azusa и Roxy (например, карты, добавленные в бенчмарк позже их последней калибровки, или отдельный набор свежих карт). Если такого чистого набора нет, это нужно прямо сказать в итоговой таблице.
- Итоговые цифры показываются пользователю таблицей: средняя ошибка, смещение, доля в пределах ±1 уровня, по категориям паттернов, в сравнении с Mixed, Roxy, Azusa, Daniel, Companella и Sunny.

### Приложение

- **Electron** (решение строителя): одно окно на HTML/JS. JS-калькуляторы и WASM MinaCalc работают в нём напрямую. Выход — один установщик или переносной `.exe` для Windows. Размер ~100–150 МБ допустим.
- Окно приложения не должно подвисать: расчёт идёт в фоне (worker), а окно обновляется по готовности.
- **Обновления** (решение строителя). Автообновления и проверки версии в интернете нет, приложение полностью офлайн. Новая версия раздаётся вручную: пользователь присылает друзьям новый `.exe`. Версия приложения видна в окне. Если tosu запущен, а osu! открыта, но карта не определяется дольше ~10 секунд, окно пишет: «osu! обновилась? Нужна новая версия приложения».
- Подпись кода не делается. Друзей нужно предупредить, что Windows SmartScreen или антивирус может один раз спросить, запускать ли программу.

## Ограничения

- Только Windows, только osu!stable, только 4K рис (доля LN ≤ 15%, как в Mixed).
- Без интернета для работы. Всё считается локально.
- Отношение ppy к чтению памяти: инструменты вроде tosu годами используются без известных банов, но официально не одобрены. Это принимается.

## Что решено пользователем

- Сценарий: выбор карты в song select.
- Только 4K рис.
- Нужен один сводный, максимально точный дан и паттерн.
- Вид — карточка B (дан, уверенность, доли паттернов, Tech/BPM/длина).
- Отдельное окно, не оверлей поверх игры.
- Без отдельной установки tosu: tosu внутри, скрытый, не открывает сайт.
- osu!stable.
- Раздавать друзьям, у них разные экраны.
- Интерфейс на русском.
- Пока без лицензий и публикации.
- Подписи «Gamma low / low/mid / mid / mid/high / high».

## Решения строителя (пользователь может поправить)

- Electron, ядро на JS, переиспользование кода LeoBlack.
- Настройки tosu, перечисленные выше.
- Пять ступеней и числовая шкала LeoBlack. Короткие имена без «Reform» и «Emik».
- Правило метки Tech (неровный ритм + MSD Technical).
- Ниже 1-го и выше Kappa — подписи «ниже 1 дана» / «выше Kappa».

## Оставлено строителю

- Точный список признаков, тип сводной модели, гиперпараметры, способ оценки уверенности.
- Порог MSD для Tech и подписи уровней уверенности («высокая/средняя/низкая»).
- Устройство кеша, обработка ошибок, ожидание osu!.
- Внешний вид окна в рамках карточки B: цвета, шрифты, компактный режим.
- Как именно встроить tosu (версия, где хранить конфиг, как прятать процесс).
- Чем собирать установщик (electron-builder или аналог).
