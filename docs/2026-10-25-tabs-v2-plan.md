# Вкладки v2: Анализ, Рейт, Марафон, Подбор — план реализации

> **Для агентов-исполнителей.** Обязательный навык: `superpowers:subagent-driven-development` (рекомендуется) или `superpowers:executing-plans`. Каждая задача идёт по TDD: сначала падающий тест, потом код, потом зелёный `npm test`. Шаги отмечены чекбоксами (`- [ ]`).

**Цель.** Добавить в четыре вкладки то, что выбрал пользователь:
- **Анализ:** график сложности по ходу карты, сравнение «для тебя», лестница рейтов, полоса паттернов.
- **Рейт:** рейт под дан, несколько рейтов за раз, зеркало и no-LN, пресеты.
- **Марафон:** автомарафон, шаблоны курсов, кривая сложности.
- **Подбор:** план тренировки, похожие карты, избранное с экспортом в collection.db, прогресс.

**Архитектура.**
1. **Фаза 0 «Фундамент»** — один агент, последовательно. Делает общие сервисы и разносит обработчики из `app/main.js` по модулям вкладок. В общих файлах расставляет помеченные блоки и после этого «замораживает» их.
2. **Фаза 1** — четыре потока параллельно (A — Анализ, R — Рейт, M — Марафон, P — Подбор). Файлы у потоков **не пересекаются**.
3. **Фаза 2 «Интеграция»** — слияние, общий `npm test`, живая проверка всех связок между вкладками.

**Стек.** Без изменений: Node 24 ESM, `node:test`, Electron 38. Новых зависимостей нет.

**Исходные дизайны.** Четыре дизайна вкладок из воркфлоу `tabs v2` от 2026-10-25. Здесь они пересказаны полностью, вместе с правками интегратора (§2). Исполнителю других источников не нужно.

**Не трогаем: вкладку «Создать карту».** Её параллельно переделывает другой план (`docs/2026-10-25-mapgen-v3-plan.md`, файла может ещё не быть). Под запретом:
- `app/renderer/createTab.js`, весь `src/gen/*`, секция `#create-tab` в `index.html`;
- обработчик `generate-map` и `generatorClient` в `app/main.js`;
- правила CSS вкладки создания.

Импортировать из `src/gen/request.js` (`LEVELS`, `STEPS`, `targetNumeric`) и `src/gen/osz.js` (`buildOsz`) можно, но **только для чтения**. Если mapgen-v3 поменяет эти экспорты, подстраивается одно место — `app/renderer/danSelect.js`.

### 1.4 Правила кода, которые держат общие тесты зелёными
1. **Init-код вкладки** — всё, что вызывается из `initRateTab`, `onRateTabShown`, `initMarathonTab`, `initRecommendTab`, `onRecommendTabShown`. Ограничения:
   - из DOM — только `document.getElementById` и `document.createElement`, потому что `fakeDom` в `i18n-tabs.test.js` больше ничего не умеет;
   - новые методы `window.danApi` вызываются через `?.` и имеют запасной вариант: `danApi.ratePresets?.() ?? Promise.resolve({ ok: false })`.
2. **localStorage** читается и пишется только в `try/catch`. В тестах его нет.
3. **Ключи i18n собираются только литералами в двойных кавычках:** `t("rate.batch.count")` или таблица `{ easy: "analysis.fit.band.easy" }`. Шаблонные строки вида `` t(`rate.${x}`) `` запрещены: проверка «каждый ключ используется» (F12) ищет литералы.
4. **Кириллица в коде** допустима только в строках-именах папок на диске, и только из списка `ALLOWED` в `tests/i18n-coverage.test.js`. Фундамент добавит туда `"коллекции"` и `"марафон"`. Пишется ровно так, в двойных кавычках: `path.join(dir, "марафон")`.
5. **`register*Ipc(deps)`** только вешает каналы и хуки. Никакого I/O, таймеров или сетевых вызовов при регистрации: `tests/registerIpc.test.js` вызывает все регистраторы с заглушками.
6. **Обработчики IPC никогда не бросают исключений.** На всё отвечают `{ ok:false, message }`, всё, что пришло из renderer, проверяют. URL строит только main.

### 2.1 `app/analysisService.js`
```js
createAnalysisService({ worker, cache, log = () => {}, getLang })
// → {
//   analyze(osuText, rate)                       // передний план: кеш → тот же запрос, если уже идёт → worker.analyze
//   analyzeQueued(osuText, rate, { isCancelled }) // тот же кеш; к воркеру — через FIFO, в полёте не больше 1
//   enqueue(fn, { isCancelled })                  // общий фоновый слот для любого задания (details у Анализа)
//   stats()                                       // { hits, misses, queued, inFlight }
// }
```
Правила кеша — те же, что в `selectionController`:
- `kind !== "error"` → `cache.set(cacheKey(text, rate), result)`;
- ошибка без `transient` → память `${lang} ${key}`, на диск не пишется;
- ошибка с `transient` → не хранится нигде;
- если в момент выхода из очереди `isCancelled()` → ответ `{ kind:"error", transient:true, cancelled:true, message:t("app.shared.cancelled") }`, воркер не вызывается, ничего не кешируется.

### 2.2 `src/rate/rateForDan.js` (чистая функция)
```js
rateForDan({ analyze, osuText, target, min = 0.5, max = 2, step = 0.05, tolerance = 0.05,
             maxTries = 10, isCancelled = () => false, onTry = () => {} })
// → { ok:true, rate, numeric, label, primary, result, base, reached, tries:[{rate,numeric}],
//     reason:"hit"|"closest"|"above-range"|"below-range" }
//   | { ok:false, reason:"base-failed"|"cancelled", result }
```
Алгоритм:
1. Проанализировать ×1.0. Если не `ok` → `base-failed`. Если `|numeric − target| ≤ tolerance` → `hit` при 1.0.
2. Направление `dir = sign(target − base.numeric)`. Сетка от 1.0 к `max` (или `min`) с шагом `step`, каждый рейт округлён до 0.01.
3. Проверить край сетки. Если анализ на краю упал, сдвинуться на один шаг внутрь, не больше двух раз. Если край не дотягивает до цели → `above-range` (или `below-range`), `rate` = край, `reached:false`.
4. Бинарный поиск первого рейта, который достаёт цель (считаем, что дан растёт с рейтом). Упавший рейт пропускается и никогда не выбирается. Останов раньше: проба попала в `tolerance` (`hit`) или кончились `maxTries` (`closest`).
5. Итог — **лучшая из всех проб**: ближе всех к цели, при равенстве ближе к 1.0. `reason = hit`, если попали в `tolerance`, иначе `closest`.
6. `isCancelled` проверяется перед каждым анализом; `onTry({ rate, numeric })` вызывается после каждого.

Сколько проб выходит: при шаге 0.01 на отрезке 1→2 это 1 + 1 + 7 = 9 ≤ 10; при шаге 0.05 на 0.8–1.45 — не больше 6.

### 2.3 Профиль: `app/profileService.js` и `app/renderer/profile.js`
**Main:**
```js
createProfileService({ recommender, store /* jsonStore userData/profile.json */, send, log, now = Date.now, retryMs = 60_000 })
// current() → { ok:true, player:{id,username,avatarUrl}, skill } | { ok:false }
// ensure({ query } = {}) → тот же ok-ответ | { ok:false, reason:"none"|"failed", message? }
//    порядок: текущий игрок recommender → сохранённый { id, username } → loadPlayer(username, {id, name}) → подсказка query
//    → иначе reason "none"; одна загрузка за раз; после неудачи до retryMs отдаёт ту же неудачу без запроса
// remember(query, loaded)  // после любой удачной загрузки: сохраняет {query,id,username}, шлёт "profile-changed"
registerProfileIpc(deps)  // "profile-get", "profile-ensure"
```
`createRecommendHandlers` получает зависимость `onPlayer(query, loaded)` и вызывает её в `player()` после удачной загрузки. В `registerRecommendIpc` она подключена к `profile.remember`.

**Renderer:**
```js
getProfile()     // { state:"idle"|"loading"|"ready"|"none"|"failed", player?, skill?, message? }
onProfile(cb)    // → unsubscribe; зовётся при каждой смене состояния и на "profile-changed"
ensureProfile()  // не чаще раза за сессию (после "failed" — снова не раньше чем через 60 с);
                 // подсказка query = rec-settings.query, если source !== "manual" (чтение в try/catch)
```
Если у `danApi` нет методов профиля (старый fake в тестах), состояние становится `"none"`, исключения нет. Если `invoke` отклонён (например, в smoke-скрипте нет обработчика), состояние становится `"failed"`, исключение тоже не вылетает.

Сюда переносятся из `main.js` и `recommendIpc.js`: `validRate(r)` (0.5–2), `validDiff(v)` (null или 0–10), `positiveId(v)`, `danOf(v)`, `MIN_DAN`, `MAX_DAN`. `recommendIpc.js` импортирует их отсюда, поведение не меняется.

### 2.6 `app/hooks.js` и `selectionController`
- `createHooks()` → `{ on(name, fn) → off, emit(name, payload) }`. Имена: `"result"` и `"window-load"`. Исключение в подписчике ловится и пишется в лог.
- `createSelectionController({ …, onResult })`: после каждого `run()`, который не был перебит новым выбором, вызывается `onResult({ key, text, rate, result })`. Сюда входят и попадания в кеш, и ошибки. Повторный показ того же `currentResult` вызова не даёт.
- Вид результата получает `key`: `{ screen:"result", result, key }`, если `key` известен. При ошибке чтения файла `key` нет, и старый `deepEqual` в тесте остаётся верным.

### 2.7 Мелкие правки чужих областей (делает фундамент до старта потоков)
- `src/recommend/recommend.js`:
  - `currentPlayer()` → `{ id, username, avatarUrl, skill } | null`;
  - `playedMaps()` → `{ played: Map, partial }` для текущего игрока; без игрока — `{ played: new Map(), partial: false }`.
- `src/recommend/skill.js`: `targetForWindow({ skill, manualDan, patternId, dan:[a,b], msdOffset = null })` → та же форма, что у `targetFor`, с `goalId:null`. `targetFor` вызывает его с `goal.dan` и `goal.msd`.
- `src/recommend/download.js`: дедупликация по `beatmapsetId` во время закачки. Второй вызывающий получает тот же Promise; его `onProgress` при этом молчит, это записано в комментарии.
- `app/renderer/rateTab.js`: `export function openRateAt(rate)`. Он ставит `pendingRate`; ближайший `refresh()` берёт его вместо `currentRate()` и сбрасывает.

## 7. Поток M — Марафон

**Подход.**
- Автомарафон **заполняет существующий список** и `.osz` сам не собирает: рейты, порядок и строки можно поменять до нажатия «Создать марафон».
- Шаблоны — данные, которыми пользуются и автоподбор, и список, собранный руками.
- Кривая рисуется по тем же числам, что и фон.

### Интерфейс. Ключи в `marathon.js`: `marathon.auto.*`, `marathon.curve.*`, `marathon.tpl.*`, `marathon.html.*`, `marathon.err.*`; количество карт — через `plural()`
**Новая группа над «Карты по порядку»: «Автомарафон» / "Auto-marathon".**
- **Шаблон / Template** (select, под ним строка-подсказка):
  - «Дан-курс (4 карты)» / "Dan course (4 maps)": «Четыре карты одного дана, каждая чуть сложнее» / "Four maps of one dan, each a bit harder";
  - «Стамина-марафон» / "Stamina marathon": «4 длинные карты (4+ мин): JS/HS/стамина» / "4 long maps (4+ min): JS/HS/stamina";
  - «Разминка → вызов» / "Warm-up → challenge": «5 коротких карт: от −1.2 до +0.3 дана» / "5 short maps: from −1.2 to +0.3 dan";
  - «Свой» / "Custom": поля «Карт» / "Maps" (3–6) и «Шаг» / "Step" (0.1–0.4).
- Шаблон заодно ставит паузу, OD/HP и название (например, «Gamma Dan Course»).
- **Финальный дан / Final dan** (радиокнопки):
  - «по профилю из «Подбора»» / "from my Picks profile": показывает «Профиль: {name}, {tile}: {dan}» через `profile.js`; без игрока — «Профиль не загружен — загрузи его во вкладке «Подбор» или выбери дан вручную.» / "No profile loaded — load one on the Picks tab or pick a dan by hand.";
  - «вручную» / "manual": `danSelect.js`.
- **Паттерны (1–3) / Patterns (1–3):** чипы из `REC_PATTERNS`, шаги идут по выбранным паттернам по кругу.
- Галочки: «не брать сыгранные» / "skip maps I've played" (только с профилем); «только ranked / loved» / "ranked / loved only".
- Кнопки «Подобрать карты» / "Pick maps" и «Стоп» / "Stop". Если список не пуст: «Заменить список» / "Replace list" или «Добавить в конец» / "Append".
- **Ход:**
  - «Карта {i}/{n}: ищем {pattern} ≈ {dan}…» / "Map {i}/{n}: looking for {pattern} ≈ {dan}…";
  - «…нашли в Songs» / "…found in Songs";
  - «…скачиваем {name} — {pct}%» / "…downloading {name} — {pct}%";
  - «…подгоняем рейт» / "…fitting the rate".
- **Итог:**
  - «Готово: {maps} подобрано — проверь и жми «Создать марафон».» / "Done: {maps} picked — check them and press “Create marathon”.";
  - «Карта {i}: подходящей не нашлось ({reason})» / "Map {i}: nothing fitting found ({reason})";
  - «Карта {i}: даже на {rate}x только {label}» / "Map {i}: only {label} even at {rate}x".
- Выбор в панели запоминается в `localStorage["marathon.auto.v1"]` (try/catch).

**Блок под списком: «Кривая сложности» / "Difficulty curve".**
- Полоса SVG:
  - ось x — время: каждая карта — отрезок шириной в её обрезанную длину на её рейте, паузы — тонкие серые полосы;
  - ось y — наш дан: ступенчатая линия, у каждой карты точка с подписью;
  - при активном шаблоне пунктиром план: «план шаблона» / "template plan".
- Итог: «Всего {time} · {maps} · {from} → {to}» / "Total {time} · {maps} · {from} → {to}".
- Предупреждения:
  - «Карта {i} легче предыдущей ({delta})» / "Map {i} is easier than the one before ({delta})";
  - «Скачок {delta} между {a} и {b}» / "Jump of {delta} between {a} and {b}" (при скачке больше 0.5).
- Та же кривая в уменьшенном виде на фоне 1920×1080, под списком карт.

### Как работает автоподбор
1. **Цели.** Main проверяет запрос и берёт финальный дан: `deps.profile.current()` + `playerDanFor` для плитки паттерна, либо дан, выбранный вручную. `stepTargets(template, finalDan)` даёт цель каждого шага.
2. **Поиск.** Для шага с целью `d`:
   - окно `targetForWindow({ manualDan: d, patternId, dan: [-0.5, +0.2] })` — дан трекера нужен только для отбора кандидатов, а окно смещено вниз, потому что ускорить карту — обычный способ её «дотянуть»;
   - `searchParams` + `trackerApi.searchMaps` (кеш 60 с);
   - `rankSets(items, target, { played, hidePlayed: skipPlayed })`, где `played` из `recommender.playedMaps()`;
   - сеты, уже взятые на прошлых шагах, выбрасываются; остаются 3 лучших кандидата.
3. **Файлы.**
   - `songsIndex.find(setId, beatmapId)` ищет в локальной папке Songs, только чтение.
   - Если карты там нет: `downloader.download` (тот же экземпляр из `deps`) сохраняет `.osz` в `скачанные`, а `extractChart` копирует только нужный `.osu`, его аудио и фон в `скачанные/марафон/<setId>/`.
   - **В папку osu! не пишется ничего.**
4. **Рейт.**
   - `rateForDan({ analyze: analysis.analyzeQueued, osuText, target: d, min: 0.8, max: 1.45, step: 0.05, isCancelled })`.
   - Промах больше 0.15 → следующий кандидат. Не подошёл ни один → оставить ближайший и добавить предупреждение.
5. **Ответ.** Main возвращает записи. Renderer добавляет их обычными строками, уже с `rate`, `label`, `numeric`, `cutMs`, и перерисовывает кривую.

**Отмена.** Токен проверяется между фазами. Закачка, которая уже идёт, докачивается в фоне и остаётся файлом в кеше.

**Проверки в `marathon-auto`:**
- `templateById` и `patternById` для каждого id;
- `manualDan` в пределах `MIN_DAN`–`MAX_DAN` (`app/validate.js`);
- `count` 3–6, `step` 0.1–0.4;
- одновременно только один автоподбор, второй получает `marathon.err.autoBusy`;
- пути, которые renderer потом присылает в `marathon-create`, для автозаписей создаёт сам main.

## 8. Поток P — Подбор

Проверено вживую (только GET):

### Оболочка

Если профиль сейчас грузится, ждём `ensureProfile()`.

### (a) План тренировки
- **Управление:** «Карт: 5 / 6» / "Maps: 5 / 6". Чипы паттернов здесь — множественный выбор, 1–3 паттерна, слоты идут по ним по порядку. Фильтры длины и ranked используются те же. Кнопка **«Составить план» / "Build plan"**.
- **Слоты** считаются от дана плитки игрока (или дана, выбранного вручную) через `targetForWindow`; смещения MSD — из `GOALS`.
  - 5 карт: разминка [−0.7, −0.35], разминка [−0.35, −0.05], рост [0, 0.25], рост [0.25, 0.5], челлендж [0.5, 0.9].
  - 6 карт: рост делится на три слота [0, 0.2], [0.15, 0.35], [0.3, 0.5].
- **Отбор:**
  - на каждый паттерн один широкий поиск от наименьшего `lo` до наибольшего `hi` его слотов, 3 страницы;
  - для каждого слота `rankSets(items, slotTarget, {played, hidePlayed:true})`, берётся лучшая карточка, кроме сетов и чартов, которые уже взяты (`titleKey` / `sameChart`);
  - пустой слот получает один собственный поиск (страница 0).
- **Карточка:** бейдж роли «Разминка» / "Warm-up", «Рост» / "Growth", «Челлендж» / "Challenge"; кнопка **«↻ Другая» / "Another"** берёт следующего кандидата слота из сессии плана, без запроса.
- **Заголовок:** «План: Stamina gamma+ (13.26) · 5 карт · ≈ 17:20» / "Plan: Stamina gamma+ (13.26) · 5 maps · ≈ 17:20".
- **Низ:**
  - «Скачать всё» / "Download all" — по одной через `rec-download`;
  - «Всё в избранное» / "All to favourites";
  - «Рейты под план» / "Rates for the plan" — `rec-ours` с центром слота, по одной карточке.

### (b) Похожие
- Небольшая секция под карточкой, до 5 компактных карточек без обложки. Заголовок «Похожие на эту» / "More like this".
- Метки: «очень похожа» / "very similar" (sim ≥ 0.8), «похожа» / "similar" (≥ 0.6), иначе «отдалённо» / "loosely".
- **Поиск:** `patterns = seed.primaryPattern`, дан = seed.dan ± 0.35, те же правила vibro и LN, 2 страницы.
- **Расстояние** (каждый член зажат ≤ 1):
  `d = 0.35·|Δdan|/0.35 + 0.25·mean|ΔMSD|/2 + 0.2·mean|Δpatterns|/0.3 + 0.12·|ΔBPM|/60 + 0.08·|Δlen|/120`;
  `sim = 1 − d + 0.05·popularity`.
- **Исключаются:** сет самой карты, перезаливы и, при включённом «не показывать сыгранные», сыгранные.
- `toCard` добавляет `seed: {primaryPattern, msdAll (7 осей), patternsAll (8), bpm, lengthSec, dan}` с округлением до 0.01, ≈150 Б на карточку. Существующие поля карточки не меняются (§1.5).

### (c) Избранное и collection.db
- **Хранение:** `userData/favourites.json` = `{version:1, items:[{beatmapId, beatmapsetId, artist, title, version, creator, dan, danLabel, bpm, lengthSec, cover, seed, addedAt, md5?}]}`.
  - не больше 500, новые сверху, без повторов `beatmapId`;
  - пишет только main, через `jsonStore`.
- **Вид:** компактные карточки с ✕ и «Похожие»; поле «Имя коллекции» / "Collection name" (по умолчанию «Lunacy mania picks»); кнопка **«Экспорт в collection.db» / "Export to collection.db"**.
- **Экспорт:**
  - для записей без md5: скачать **байты** (`fetchBytes` в `recommendIpc`), проверить `[HitObjects]`, посчитать md5 (`node:crypto`); по три одновременно; md5 сохраняется в запись;
  - файл пишется в `Documents/<docsDir>/коллекции/collection.db`, имя папки — литерал `"коллекции"`; **в папку osu! никогда**;
  - недоступная карта пропускается и попадает в счётчик пропусков.
- **После экспорта:**
  - «Готово: 42 карты, пропущено 1» / "Done: 42 maps, 1 skipped" и кнопка «Показать файл» / "Show file";
  - подсказка: «Для osu!stable: добавь через Collection Manager (merge), не заменяй свой collection.db» / "For osu!stable: merge it in with Collection Manager, don't overwrite your own collection.db".
- **Формат:** Int32 версия 20150203, Int32 число коллекций; на каждую — имя, Int32 n, n × md5. Строка: 0x0b, длина в ULEB128, байты UTF-8; пустая — 0x00.

### (d) Прогресс
- **Журнал подборов:** `userData/picks.json`, до 1000 записей `{beatmapId, beatmapsetId, artist, title, version, dan, danLabel, how:"download"|"direct"|"fav", at}`; выигрывает первый `at`.
  - Пишется в `download`, `open` и `fav-add`.
  - Данные карточки берутся из `cardIndex` — LRU на 3000, его заполняют ответы `start`, `more`, `plan`, `similar`.
- **Вид:** чипы периода «7 / 30 / 90 дн» / "7 / 30 / 90 days".
  1. «Сыграно 7 из 15 подобранных» / "Played 7 of 15 picks". В каждой строке одно из:
     - «✓ 96.3% · 1.1x · 3 дн. назад» / "✓ 96.3% · 1.1x · 3 days ago";
     - «✗ не пройдена» / "✗ failed";
     - «не сыграна» / "not played yet" и osu!direct.
  2. «Дан: gamma+ → delta-- (+0.4)» / "Dan: gamma+ → delta-- (+0.4)", дальше изменения MSD от большего к меньшему. Под ними SVG-график с чипами осей (Overall/Stream/…); точки — когда играли подобранные карты.
  3. Приглушённая заметка: «mania-tracker видит ~70 последних игр и топ-200 по каждой оси» / "mania-tracker only sees the last ~70 plays and the top 200 per axis".
- **Сопоставление.** Игра засчитывается, только если была после подбора:
  - из `recent` — по точному времени; выигрывает лучшая пройденная игра, попытки считаются;
  - иначе по `playedAt` из skill-plays, с точностью до дня; `tracker.playedMaps` теперь хранит `playedAt`.
